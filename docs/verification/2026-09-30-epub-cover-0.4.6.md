# 0.4.6 验证档 —— EPUB 封面提取 + 封面/插图页修复

日期：2026-09-30
版本：**0.4.6 / versionCode 18**

## 需求（用户真机反馈）

部分 EPUB（文字 + 插图型，如 calibre 制作的轻小说）中**封面与插图不显示**，阅读时在该位置只见"封面""插图"几个字、无任何图。

## 根因（3 个叠加）

1. **插图未渲染（文本管线既有边界）**：文本版 EPUB 走纯文本管线，图片标签被剥离；且本样本的图是 **SVG 包裹**（`<svg><image xlink:href=.../>`），连"图片版快速判定"（`<img` 前缀正则）都躲过了，整本走了文本管线。
2. **`<head>` 未剥离**：`htmlToParagraphs` 保留了 `<title>` 文本 ——"封面""插图"二字成为正文段落与章节标题；叠加 SVG 封面页正文为空，观感即"只有几个字、啥也没有"。
3. **封面缺失**：EPUB 真实封面图（`<meta name="cover">`）从未被读取；书库封面一直是"第 0 页文字合成"。

## 改动清单（用户选择 A 方案：封面提取）

1. `NovelTextExtractor`
   - `parseOpf` 采集 `<meta name="cover">` 与 item `properties`；
   - 新增封面解析链：meta cover（manifest id 或文件名）→ EPUB3 `cover-image` → href 含 cover 兜底；封面字节读取（8MB 限幅防御）；
   - `EpubTextData` 增加 `coverBytes`；
   - **空文档不生成空章节**（SVG 封面页 / 插图页整体跳过）；
   - `htmlToParagraphs` 增加**剥 `<head>` 整块**（title/meta 不再进正文）。
2. `NovelPageSource`：`open`/构造接受 `coverBytes`；`renderCover()` 优先使用书内封面图（长边 1024~2047 降采样解码），失败回退原第 0 页文字合成。
3. `ArchiveFactory`：EPUB 打开路径透传 `coverBytes`。
4. 版本 0.4.6 / versionCode 18。

## 踩坑记录（重要，已录入 skill）

**Kotlin 块注释支持嵌套**：注释里写 `media-type image/*`，其中的 `/*` 使注释再加深一层，**后续大段代码被整体吞进注释**，直到 590 行正则有里 `*/` 意外闭合，表现为远离真凶的 `Expecting member declaration` 报错；逐块回滚二分才定位。教训：注释里勿出现 `/*` 序列。

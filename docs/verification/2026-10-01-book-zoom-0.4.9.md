## 背景（用户反馈）

1. 左右翻页模式（图片书/漫画）双击放大后**每页各自为战**：翻一页就弹回 1x，等于逐页单独放大。
2. 上下连续模式双击放大时，**动画期间内容漂移、结尾瞬跳**，连续页不衔接。

两处都已读到确切代码路径（`ReaderScreen.kt` 的 `ReaderPagerArea`）：

- 横向：所有页共用同一个 `pageZoom`（`ReaderPage(zoomState = pageZoom)`，graphicsLayer 同 scale/offset），
  但 `LaunchedEffect`（原 491-496 行）**在翻页时无条件 `pageZoom.reset()`**，于是共享状态每次翻页即清零
  → 表现为「单独放大、翻页即弹回」。
- 上下：双击的 `animate(from, to, tween(200))` 每帧只写 `columnZoomState` 的 scale，
  而 `requestScrollToItem` 在 `animate` **之后**才执行一次（原 561-569 行）→ 动画期间滚动偏移停在起点、
  内容随 scale 放大而漂移，动画结束瞬间跳到正确位置（用户感知：漂移 + 瞬跳）。

## 机制说明

### 横向（图片书）整本统一缩放

所有页本来就共用同一份 `PageZoomState`（scale + offset），「放大原点一致」由 `graphicsLayer` 默认
`TransformOrigin.Center` + 同一 offset 保证。真正的缺陷是翻页复位，现在：

- 图片书（`!isTextNovel`）翻页**不清零** → 翻到哪一页都是同一 scale/offset；
- 文字小说（`isTextNovel`）保持翻页复位（需求 4）；
- 缩放中 `userScrollEnabled = false` 防拖拽冲突不变，翻页走**三分点按**（`detectTapGestures` 的 onTap
  不消费移动事件，`pageZoom` 对静止点按也不消费任何事件——已在测试中实证「缩放中点按右分区可翻页」）；
- 再双击 → `togglePageZoom` 动画回到 1x 并 `reset()`（offset 清零）。

### 上下（连续页）动画逐帧锚定

`animate` 回调每帧：①写 scale；②用 `anchorForScale` 按**当前帧** scale 重算落点；③`requestScrollToItem`。
由于每帧从冻结的 `pixel` 重算，焦点处的文档点在 1x↔2.5x 全程停在双击位置；动画结束帧的落点与旧实现
最后一次 `requestScrollToItem` 的结果完全相同 → 结尾状态不变、不瞬跳。

### 2) 两个端到端测试的**反证实验**（证明它们不是空过）

新增的两个 Compose 测试都对旧行为做过反向验证，改回旧实现即失败、改回来即通过：

- `MangaUnifiedZoomTest`：把复位改回无条件 `pageZoom.reset()` →
  `AssertionError: 翻页后缩放应保持，横滑不应翻页`（精确挂在被修复的那条行为上）。
- `ContinuousZoomAnchorTest`：把滚动挪回 `animate` 之后（旧接线）→
  `AssertionError: scale=1.025 时焦点文档点漂移（动画期间应逐帧锚定） expected:<360.0> but was:<351.2195>`
  （第一帧就开始漂移）。

两个测试的可观测口径：

- 横向用 `userScrollEnabled = pageZoom.scale <= 1f` 的副作用——缩放中横滑不翻页、缩回 1x 后横滑能翻页
  （后者是正向对照，确保「不翻页」不是因为滑动失灵）。测试末尾还有「缩回 1x → 横滑翻到第 3 页」的正向断言。
- 上下用页面语义节点 `boundsInRoot` 反推几何：页高 = 240 × scale、滚动偏移 = 240 × 下标 × scale − 屏幕 top，
  于是 `焦点文档点 = (滚动偏移 + 焦点 y) / scale` 可逐帧采样。
  **注意 `boundsInRoot` 是裁剪后的边界**（贴边页会伪装成「更矮」），故只取上下都离视口边 ≥1px 的页反推。
  测试用手动时钟（`mainClock.autoAdvance = false`）冻结动画、逐帧推 40 帧采样，并自证
  `scales.any { it in 1.2..2.4 }`（确实采到中间帧，不是等动画跑完才断言）。

## 待真机确认（用户）

1. 漫画（CBZ/PDF）左右翻页 → 双击放大 → **连翻数页**：每页都应是同一放大区域（同一放大原点）、不弹回 1x；
   再双击整本缩回 1x。
2. 同上，放大状态下**点按左/右 1/3 分区**应能翻页；**注意屏幕垂直中央偏右**有一枚常驻手势锁钮（见遗留问题 1）。
3. 文字小说（TXT / 文字版 EPUB）左右模式：翻页仍复位缩放（保持旧行为）。
4. 上下连续模式 → 双击放大/缩回：动画期间内容应「跟着手不动」地放大，页页始终首尾相接、不停顿不跳。
5. 上下连续模式 → 双指捏合放大（含捏合后单指水平平移、纵向滚动）无回归。
6. 日漫右开本（RTL）横向：三分点按方向仍镜像正确（左 1/3 下一页）；双击放大与上面一致。

## 遗留问题与发现（未在本次改动范围内）

1. **右侧中央常驻手势锁钮与「右 1/3 点按翻页」分区重叠**（既有交互冲突，非本次引入）：
   锁钮为 36dp、`align(CenterEnd)`，屏幕 360dp 宽时占据 x≈318-354、y 居中 ±18dp。
   在该区域点按会**点中锁钮进入锁定态**而不是翻页——本次测试里点按位置必须避开它才成立（测试注释已写明）。
   建议后续把锁钮移出点按分区，或在其上做「先翻页、长按才锁定」的处理。
2. `scripts/copy-delivery.py` 会把 `app/build/outputs/apk/debug/app-debug.apk` 一并拷成
   `XY-READER-<版本>-debug.apk`，**该 debug APK 可能是上一版本的陈旧产物**：本次它实为 0.4.8
   （versionCode 20，02:09 构建），已删除该错标签文件，只交付 release APK。
   如需 debug 交付物，建议脚本先校验 APK 内的 versionName 再拷。
3. 横向整本缩放复用同一 `PageZoomState`，因此 `PAGE_MAX_ZOOM = 5x` 与 offset 钳制（按页容器尺寸）也整本共用：
   不同宽高比的页混排时，钳制范围按最后测量的页尺寸计算（所有页同尺寸时无差异）。
4. 上下模式的**捏合**仍是「逐事件」锚定（`zoomAnchored`，每个手势事件重算一次），与双击的逐帧锚定共用同一数学；
   捏合无动画，无漂移问题。

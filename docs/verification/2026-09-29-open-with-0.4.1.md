# 0.4.1 外部「打开方式」修复 — MT 管理器反编译实证版（2026-09-29）

## 背景

0.4.0（同功能首版）在用户真机上**依旧不出现**于 MT 管理器/文件管理器的「打开方式」。
用户要求：先调研取证、并行子代理、备好回滚。

## 调查过程（三路并行子代理 + 本机取证）

### ① 生态调研（子代理 A）
- 文件管理器用 `queryIntentActivities(ACTION_VIEW intent)` **自建列表**；`MATCH_DEFAULT_ONLY` 要求过滤器含 DEFAULT
- 关键实证：文件管理器的 `content://` URI **常无扩展名**（`content://media/external/file/85139`），
  MIME 常为 `application/octet-stream` → 我们原 5 组过滤器（①MIME白名单无octet / ②③靠路径扩展名）**全部失配**
- 「改清单后系统会缓存旧关联，需**卸载重装**」

### ② 成熟样本逐字对比（子代理 B）
- LibreraReader / KOReader / anx-reader / VLC 四份真实清单：全部含 `application/octet-stream` 或
  「scheme+host 不限路径」「裸 */*」的兜底组；SEND 用裸 `*/*`
- ⚠️ 其「OPENABLE 会自伤」的推理被**本站真引擎测试当场证伪**（加三分类后 {DEFAULT} 单分类 intent 依然全命中）

### ③ MT 管理器 APK 反编译取证（子代理 C，本次决定性证据）
- 拿到 MT2.26.9 官包（bin.mt.plus，36.5MB）并反汇编 classes*.dex：
  - **「打开方式」= `Intent(ACTION_VIEW)` + `setDataAndType(uri, mime)` + 完全不添加任何 category
    + `queryIntentActivities(intent, 0x10000=MATCH_DEFAULT_ONLY)`，content://、file:// 各查一次**（硬证据：字节码逐指令）
  - 全 dex **零命中** `CATEGORY_BROWSABLE`/`CATEGORY_OPENABLE`；`QUERY_ALL_PACKAGES` 已声明（可见性非原因）
  - MT 自带 MIME 映射表含 `application/octet-stream`（未知类型默认候选）
- 推论：成败在 **scheme + MIME 的交叉匹配**；对未知类型 MT 极可能传 octet-stream

## 修复（0.4.1）

| 改动 | 文件 | 内容 |
|---|---|---|
| 白名单补全 | AndroidManifest.xml | VIEW①与 SEND④ 的 MIME 列表补 `application/octet-stream` + `application/x-zip-compressed`（补上主缺口） |
| 分类超集 | AndroidManifest.xml | 5 组过滤器全部带 `DEFAULT+BROWSABLE+OPENABLE`（部分管理器会附加分类；超集对匹配无损——真引擎验证） |
| ① 组约束 | AndroidManifest.xml | 补 scheme content/file + host *（防列入网页链接，负例测试确认） |
| 测试保真度 | OpenWithIntentTest.kt | 助手改为**逐字节还原 MT 的调用方式**：无 category + `MATCH_DEFAULT_ONLY`；新增 MT 精确场景 + 真机形态缺口场景 |

## 装机指引（重要）

1. **先卸载旧版**（系统缓存旧「打开方式」关联，覆盖安装可能不刷新）；
